> **目标**：用纯平台数据推出 WA Excel 发票的每卡费用，不依赖任何 Excel 字段。
> **验证范围**：2025-10 ~ 2026-08（11 个月，107,277 行）
> **状态**：G ✅ 完全打通 ｜ D ✅ 8月打通 ｜ C ✅ 基本打通 ｜ E ⚠️ ｜ 其余类型待补

## 一、Excel 侧计费公式（逆向所得）

```
final_charge = final_days / DAY(LAST_DAY(final_start_date)) * monthly_rate
final_days   = DATEDIFF(final_end_date, final_start_date) + 1
```

| 要素 | 说明 |
|---|---|
| 分母 | `final_start_date` 所在自然月天数（28/30/31） |
| 单价 | 仅 4 档：$21 / $32 / $43 / $62 |
| 计费月 | `final_start_date` 所在自然月 |
| **`final_start_date`** | **不一定是月初**，等于该项的"计费起点" |

**公式验证**：126,340 / 142,902 行（88.4%）精确命中，残差 $0。

## 二、平台数据源与陷阱

### 2.1 表清单

| 表 | 用途 |
|---|---|
| `tc_cdr.sim_status_for_sftp_bak` | 主表，每小时快照（`SimStatus` / `Cycle_Start_Time` / `Cycle_End_Time` / `partition_time`） |
| `ods.resource_res_vsim_cycle_history` | **账期历史**（`cycle_time` / `next_cycle_time`） |
| `ods.resource_res_vsim_status_log` | 状态变更日志（`'作废'` / `'激活'`） |
| `ods.resource_res_vsim_product` | 产品单价（`supplier_id = 2275` = Wing Alpha） |
| `mysql_cdc_sync.wa_invoice_detail` | WA 发票（**仅对账用，规则不依赖**） |

### 2.2 必须知道的陷阱

| # | 陷阱 | 后果 |
|---|---|---|
| 1 | `Cycle_Start_Time`/`Cycle_End_Time` 是**字符串**，带 `05:00` 偏移 | 直接比较日期会错 1 天 |
| 2 | `partition_time` 是 UTC 字符串 | **不减时区**，直接用 |
| 3 | `status_log.CREATE_DATE` 是 ISO TIMESTAMP | **减 5 小时再取日期**才与账期对齐 |
| 4 | `cycle_history.package_price` **恒为 0** | 不可用作单价 |
| 5 | 产品维度表 5 个 ID 价格滞后 | 见第五节 |

### 2.3 数据完整性

| 项 | 值 |
|---|---|
| 快照覆盖 | 24 点/天，2024-07 ~ 2026-09 |
| 快照产品 ID | 350 个，全部可在产品表解析 |
| **2025-09 及 2026-09 早间分区** | **部分不可读**（`AccessDeniedException`）→ 查询必须加分区过滤 |

## 三、计费规则

### 3.0 总览

| 类型 | `final_start` | `final_end` | 状态 |
|---|---|---|---|
| **G** 整月卡 | 月初 | 月末 | ✅ **$0.00** |
| **C** 换卡旧卡 | `cycle_history.next_cycle_time`（落本月） | `作废日 − 1` | ✅ 基本打通 |
| **D** 换卡新卡 | `激活日 + 1` | `max(Cycle_End) − 1` | ✅ 8月 53/53 |
| **E** 新激活 | 月初 | `当月新账期起点 − 1` | ⚠️ 21/28 |

### 3.1 G：整月卡 ✅

```
final_start = 当月 1 号
final_end   = 当月最后一天
final_days  = 当月自然日天数
```

| 月份 | 卡数 | Excel | 计算 | 差异 | 天数命中 |
|---|---|---|---|---|---|
| 2026-07 | 7,299 | $365,719.00 | $365,719.00 | **$0.00** | 7,299 / 7,299 |
| 2026-08 | 7,137 | $353,585.00 | $353,585.00 | **$0.00** | 7,137 / 7,137 |

> 修掉了原 notebook 的 `COUNT(1) - 1` bug（月末仍在网却扣 1 天）。

### 3.2 C：换卡旧卡 ✅

```
cycle_start = cycle_history 中「next_cycle_time 落在本月内」的最早日期
              （实测 = Excel 的 cycle_start_date，318/318 命中）
作废日 zf   = status_log 中 NEXT_STATUS='作废' 且 CREATE_DATE >= 月初 的最早日期
final_start = cycle_start
final_end   = zf − 1
final_days  = DATEDIFF(final_end, final_start) + 1
```

**实例** `083901821047125315`：账期起点 08-28、作废日 09-01 → `final_end` 08-31 → `final_days` 4 → 4/31 × $62 = **$8.00** ✓

| 月份 | 卡数 | Excel | 计算 | 差异 | 天数命中 |
|---|---|---|---|---|---|
| 2026-07 | 41 | $919.65 | $822.55 | −$97.10 | 20 / 41 |
| 2026-08 | 318 | $8,578.61 | $8,446.00 | **−$132.61** | 294 / 318 |

### 3.3 D：换卡新卡 ✅（8月）

```
final_start = 激活日 + 1              （status_log '激活' 的 CREATE_DATE 减 5h，再 +1）
final_end   = max(Cycle_End) − 1      （当月快照最大 Cycle_End_Time 日期 − 1）
final_days  = DATEDIFF(final_end, final_start) + 1
```

| 月份 | 卡数 | start 命中 | end 命中 | 天数命中 | Excel | 计算 | 差异 |
|---|---|---|---|---|---|---|---|
| **2026-08** | **53** | **53/53** | **53/53** | **53/53** | $1,613.55 | $1,613.55 | **$0.00** ✅ |
| 2026-07 | 197 | 62/197 | 132/197 | 30/197 | $7,279.67 | $10,263.13 | +$2,983.46 |

**7月失配原因（已验证）**：197 张中
- **163 张** `fd = fed − fsd + 1`（正常）→ 但平台推的 `fed` 只命中 108/163
- **34 张** `fd = usage_days`（WA 把上月使用天数也算进来）→ **平台无此数据，推不出**

### 3.4 E：新激活 ⚠️

```
新账期起点 = 当月快照中 Cycle_Start_Time 落在「本月 2 号及以后」的最小值
final_start = 月初
final_end   = 新账期起点 − 1
```

| 月份 | 卡数 | Excel | 计算 | 差异 | 天数命中 |
|---|---|---|---|---|---|
| 2026-08 | 28 | $1,069.45 | $1,048.64 | −$20.81 | 21 / 28 |
| 2026-04 | 706 | $16,597.54 | $22,617.10 | +$6,019.56 | 1 / 706 |
| 2026-03 | 1,229 | $33,640.68 | $17,078.77 | −$16,561.91 | 0 / 1,229 |

> E 在小样本（8月 28 张）上成立，样本变大（3月 1,229 张）后失效 —— **说明还有未找到的分支**。
